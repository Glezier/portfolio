# Portfólio Profissional --- Glezier Montalvane

## 1. Visão geral

Desenvolver um site de portfólio pessoal e profissional que funcione
como a principal vitrine de Glezier Montalvane como desenvolvedor Full
Stack.

O portfólio deve servir principalmente para:

-   apresentar perfil e posicionamento profissional;
-   demonstrar capacidade técnica através de projetos reais;
-   apoiar candidaturas a trabalhos freelance, estágios e vagas;
-   centralizar projetos, tecnologias, experiências e formas de contato;
-   direcionar visitantes para GitHub e LinkedIn;
-   evoluir ao longo do tempo conforme novos projetos e experiências
    forem concluídos.

O site não deve ser apenas um currículo digital nem uma reprodução do
GitHub. Seu principal objetivo é **selecionar e apresentar as melhores
evidências da capacidade de desenvolver software**.

------------------------------------------------------------------------

# 2. Objetivo do produto

Um visitante deve conseguir responder rapidamente:

1.  Quem é Glezier?
2.  Em que área ele trabalha?
3.  Quais tecnologias utiliza?
4.  Que sistemas já desenvolveu?
5.  Qual é a qualidade dos projetos?
6.  Como acessar seu código?
7.  Como entrar em contato ou contratá-lo?

A prioridade da página deve ser:

**Apresentação → Projetos → Competências → Experiência → Contato**

------------------------------------------------------------------------

-   clientes procurando desenvolvedores freelance;

# 5. Princípio central

O portfólio deve seguir o princípio:

> **Mostrar, não apenas afirmar.**

Exemplos:

Em vez de:

> Conhecimento em React.

Mostrar um projeto desenvolvido em React.

Em vez de:

> Conhecimento em APIs REST.

Mostrar uma aplicação cuja arquitetura utiliza uma API REST.

Em vez de:

> Conhecimento em PostgreSQL.

Explicar como o banco foi utilizado dentro de um sistema.

Em vez de:

> Conhecimento em Git.

Manter projetos públicos, organizados e documentados no GitHub.

------------------------------------------------------------------------

# 6. Direção visual

O design deve ser:

-   moderno;
-   profissional;
-   minimalista;
-   predominantemente escuro;
-   responsivo;
-   elegante;
-   relacionado à tecnologia sem exageros;
-   visualmente consistente com uma imagem profissional de
    desenvolvedor.

## Evitar

-   excesso de ícones;
-   partículas apenas decorativas;
-   efeitos neon exagerados;
-   animações constantes;
-   dezenas de gradientes;
-   barras de habilidade em porcentagem;
-   excesso de texto;
-   aparência de template genérico de portfólio.

O objetivo é que o site se aproxime mais visualmente de um **produto
moderno de tecnologia** do que de uma página cheia de efeitos.

# 11. Estratégia para projetos

A seção **Projetos** deve ser o elemento mais importante do site.

Entretanto:

> **Nem todo repositório do GitHub deve entrar no portfólio.**

O GitHub funciona como catálogo completo.

O portfólio funciona como **curadoria dos melhores trabalhos**.

## Critérios para inclusão

Um projeto deve entrar quando demonstrar pelo menos um dos seguintes:

-   aplicação prática;
-   domínio de determinada tecnologia;
-   arquitetura interessante;
-   resolução de problema relevante;
-   desenvolvimento Full Stack;
-   backend;
-   frontend;
-   banco de dados;
-   testes;
-   segurança;
-   algoritmos;
-   integração entre tecnologias;
-   evolução técnica.

## Evitar

-   exercícios muito simples;
-   repositórios vazios;
-   pequenos testes de sintaxe;
-   projetos duplicados em propósito;
-   cópias literais de tutoriais;
-   projetos cuja autoria não seja de Glezier;
-   projetos institucionais que possam gerar uma interpretação incorreta
    de propriedade ou autoria.

------------------------------------------------------------------------

# 12. Autoria dos projetos

O portfólio deve ser especialmente cuidadoso com autoria.

Projetos pertencentes a laboratórios, instituições, empresas ou
terceiros **não devem ser apresentados como projetos pessoais**.

Caso no futuro exista alguma experiência colaborativa importante, ela
poderá aparecer na seção de experiência com descrição precisa da
contribuição realizada.

Ela não deve ser apresentada como produto próprio.

Por esse motivo, projetos institucionais do laboratório não farão parte
da seleção principal de projetos deste portfólio.

------------------------------------------------------------------------

# 36. Regra de manutenção

A cada novo projeto, perguntar:

1.  Esse projeto demonstra uma competência nova?
2.  É melhor que algum projeto atualmente exibido?
3.  Possui qualidade suficiente para representar meu trabalho?
4.  A autoria está clara?
5.  Consigo explicar suas decisões técnicas em uma entrevista?
6.  Ele ajuda um cliente ou recrutador a entender o que consigo
    construir?

Se a resposta for majoritariamente negativa, o projeto pode permanecer
apenas no GitHub.

O objetivo não é aumentar indefinidamente o número de cards.

O objetivo é aumentar continuamente **a qualidade da seleção**.
